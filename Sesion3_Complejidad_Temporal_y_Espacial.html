Punto de partida

Dos recursos que se gastan

Imagina que vas a preparar tacos para una fiesta. Para saber si te va a alcanzar, te haces dos preguntas muy distintas: ¿cuánto tiempo voy a tardar? y ¿cuánto espacio necesito en la cocina? (mesas, platos, ollas). Puedes tardar poco pero ocupar toda la cocina, o usar una sola olla pero tardar toda la tarde.

Los algoritmos funcionan igual: al ejecutarse gastan dos recursos de la computadora.

T(n) Complejidad temporal

El reloj. Cuenta cuántos pasos da el algoritmo cuando los datos tienen tamaño n. Se lee "T de n".

S(n) Complejidad espacial

La mesa. Cuenta cuántas casillas de memoria necesita el algoritmo. Se lee "S de n" (la S viene de space, "espacio" en inglés).

Definiciones

Complejidad temporal: cómo crece el número de pasos de un algoritmo cuando crece el tamaño de los datos.

Complejidad espacial: cómo crece la memoria que necesita un algoritmo cuando crece el tamaño de los datos.

Ambas se expresan con la misma notación que vimos en la sesión anterior: O(1), O(log n), O(n), O(n²)…

Primer recurso: el tiempo

Cómo contar los pasos de un algoritmo

No hace falta cronometrar. Basta con contar cuántas veces se ejecuta cada instrucción. Para hacerlo, sigue estas cuatro reglas:

  1. 1Una instrucción simple vale 1 paso (leer, escribir, asignar, comparar o hacer una operación aritmética).
  2. 2Un ciclo que se repite n veces multiplica por n lo que tiene adentro.
  3. 3Los bloques que van uno tras otro se suman.
  4. 4Al final te quedas con el término que más crece y quitas los números que acompañan. Por ejemplo, 4n + 3 se convierte en O(n).
Ejemplo: sumar y encontrar el mayor de n números

Un programa en PSeInt lee n calificaciones, calcula su suma y busca la más alta. ¿Cuántos pasos da?

LíneaInstrucciónVeces que se ejecuta
1Leer n;1
2Para i <- 1 Hasta n ... Leer datos[i];n
3suma <- 0;1
4maximo <- datos[1];1
5Para i <- 1 Hasta n ... suma <- suma + datos[i];n
6Si datos[i] > maximo ...n
7maximo <- datos[i]; (solo cuando es mayor)hasta n
Total en el peor caso4n + 3
T(n) = 4n + 3 → se quita el 4 y el 3 → complejidad temporal O(n)

¿Por qué se vale quitar el 4 y el 3? Porque cuando n es enorme (un millón de datos, por ejemplo), el 3 casi no pesa y el 4 solo cambia la rapidez de la computadora, no la tendencia de crecimiento.

Segundo recurso: la memoria

Cómo contar la memoria que usa un algoritmo

Todo dato que guardas ocupa una casilla de memoria: una variable ocupa una casilla, y una lista de n elementos ocupa n casillas. La complejidad espacial cuenta cuántas casillas hacen falta.

Acuerdo para este curso

Cuando digamos "complejidad espacial" nos referiremos al espacio auxiliar: la memoria extra que el algoritmo crea además de los datos de entrada. Algunos libros incluyen también la entrada, así que conviene aclarar siempre cuál se está usando.

Consejo de Mixtle

Cuando analices el espacio, pregúntate: "¿creo algo nuevo que crece con n?" Si solo usas variables sueltas, es O(1). Si creas una lista, una tabla o una copia del tamaño de los datos, el espacio crece con n.

Algoritmos conocidos

Tiempo y espacio lado a lado

Fíjate que ningún algoritmo es el mejor en todo. Cada uno tiene su propia combinación.

AlgoritmoTiempoEspacio extraEn palabras
Búsqueda linealO(n)O(1)Revisa uno por uno, sin guardar nada más.
Búsqueda binaria (iterativa)O(log n)O(1)Parte la lista a la mitad; requiere lista ordenada.
Ordenamiento burbujaO(n²)O(1)Lento, pero ordena en la misma lista.
Ordenamiento por mezcla (merge sort)O(n log n)O(n)Rápido, pero necesita listas auxiliares.
Observa la burbuja contra merge sort: uno gasta poca memoria y mucho tiempo; el otro, al revés. A esta situación se le llama compromiso entre tiempo y espacio (en inglés, time–space trade-off).
El corazón del tema

Gastar memoria para ganar velocidad

Piensa en las tablas de multiplicar. Podrías calcular 7 × 8 desde cero cada vez que lo necesites (tardas más), o memorizar el resultado (gastas un lugarcito en tu cabeza, pero respondes al instante). Eso es intercambiar espacio por tiempo.

Veamos un caso real con la sucesión de Fibonacci, donde cada número es la suma de los dos anteriores: 1, 1, 2, 3, 5, 8, 13…

  1. 1Recursivo ingenuo: para calcular un número vuelve a calcular los dos anteriores, y estos a su vez los suyos. Repite el mismo cálculo una y otra vez.
  2. 2Con memoria: cada resultado se guarda en una tabla la primera vez que se calcula, y nunca se vuelve a calcular. Gasta memoria, pero ahorra muchísimo tiempo.
  3. 3Iterativo: solo recuerda los dos últimos números. Es rápido y casi no usa memoria.

Los pasos del recursivo ingenuo son las veces que se llama a la función. Las barras usan escala comprimida (por potencias de diez) para que todas se alcancen a ver.
Consejo de Mixtle

Con n = 30, el recursivo ingenuo hace más de 2.6 millones de llamadas, y la versión con memoria solo 30 pasos. Un poco de memoria bien usada puede valer millones de pasos. Pero ojo: en un celular o en un dispositivo pequeño la memoria también es limitada, así que siempre hay que equilibrar.

Pon a prueba lo aprendido

Preguntas rápidas

Intenta contestar antes de abrir la respuesta.

1. Un algoritmo hace 5n² + 2n + 7 pasos. ¿Cuál es su complejidad temporal?
O(n²). El término que más crece es 5n²; el 5, el 2n y el 7 se descartan.
2. Un programa copia una lista de n nombres en una lista nueva. ¿Cuál es su espacio auxiliar?
O(n), porque crea n casillas nuevas que antes no existían.
3. Verdadero o falso: un algoritmo rápido siempre usa poca memoria.
Falso. Merge sort es muy rápido, O(n log n), pero necesita O(n) de memoria extra. Rapidez y poca memoria no siempre van juntas.
4. Menciona un ejemplo cotidiano en el que gastes memoria para ahorrar tiempo.
Guardar los contactos en el teléfono en lugar de buscar el número cada vez, o memorizar las tablas de multiplicar. En ambos casos guardas información para no repetir el trabajo.
Cierre de la sesión

Conclusión

Todo algoritmo gasta dos recursos: tiempo y memoria. La complejidad temporal T(n) cuenta los pasos; la complejidad espacial S(n) cuenta las casillas de memoria extra. Ambas se expresan con notación Big-O y se obtienen contando, sumando bloques y quedándose con el término dominante. Rara vez un algoritmo gana en las dos cosas a la vez, por eso es importante reconocer el compromiso entre tiempo y espacio y elegir según el problema: ¿tengo poca memoria o poco tiempo?
